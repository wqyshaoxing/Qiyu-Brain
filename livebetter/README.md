# livebetter

生活与健康。这是本仓库里**唯一涉及人身安全**的领域，所以先定契约，再谈技能。

## 现状

只有领域骨架，**未建阶段目录**。等第一批技能设计定了再建，避免空壳。

## 候选技能

| 阶段 | 候选 | 说明 |
| --- | --- | --- |
| input | goal-and-symptom-intake | 澄清目标、症状、既往史、用药，先分流到「日常优化」还是「就医」 |
| input | guideline-and-evidence-search | 检索指南与系统综述，记录证据等级与发布时间 |
| reasoning | risk-benefit-tradeoff | 收益、风险、可行性、依从性并列；不用单一指标下结论 |
| output | plan-draft | 可执行、可调整、有停止条件的计划草案 |
| verify | red-flag-check | 就医红旗症状、禁忌、与医生的沟通清单 |

## 安全契约（不可协商）

1. **不是医疗建议**。每份产物开头必须有一行免责声明，且不得使用确定性诊断表述。
2. **红旗优先**。出现急症指征时，唯一正确输出是「立即就医」，停止后续所有建议。
3. **证据分级独立**。不照搬学术论文的证据分级；指南、RCT、观察性研究、专家意见的权重不同，且必须标注发布日期——健康领域过时结论危害最大。
4. **不替代个体化评估**。涉及药物相互作用、剂量、孕期、儿童、基础病时，必须指向持证医师。
5. **不编造来源**。查不到就写查不到，不许用「研究表明」兜底。

## 隐私

症状、检查结果、用药记录属于高敏数据。默认只在本机工作区处理，`_memory` 里只留可公开复述的一般性结论。
